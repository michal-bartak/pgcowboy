DB command template syntax

Configure per operation under DB command templates. See sql/README.md in the repository for full details.

Execution modes

  • Function call — Write the call only (no SELECT). Placeholders become $1, $2, … For remove_role, ${rolename} is an alias for ${loginname}.
  • SQL statement — Single statement, no SELECT. Role names are embedded as identifiers (not quoted). Examples: DROP ROLE ${loginname}; GRANT ${parent_roles} TO ${loginname}.
  • PL/pgSQL block — Write the complete anonymous block yourself (DO $do$ BEGIN … END $do$;), including your own dollar-quote delimiter; the app runs it verbatim. Semicolons allowed. Pick a delimiter that can't appear in embedded values.

Placeholders

Two forms, and they are separate namespaces:

  • ${name} — a built-in, from the closed set an operation offers: ${loginname}, ${parent_roles}, ${comment}, ${new_password}, ${attributes}, ${config_name}, ${config_value}, and ${rolename} (remove_role alias). Any other name is rejected.
  • ${{key}} — a configured comment field (Settings → Comment fields), in create_role and set_comment only. Typed from the role's JSON comment; empty or absent becomes NULL.

So ${comment} is the whole comment, while ${{comment}} is a JSON key named comment. A comment field cannot be used inside the ARRAY[...] || ${...} concat form.

Function mode: do not use raw $1 or SELECT in the template. Statement/block mode: role names are identifiers, not bind parameters.

        pgCowboy
        
      

      

        A cross-platform desktop app for maintaining PostgreSQL roles across many clusters.
        Real DDL and privilege changes are performed by user-defined SQL call templates run
        against each cluster.
